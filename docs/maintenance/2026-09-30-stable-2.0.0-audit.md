## CLI and filesystem boundary

`src/main.ts` routes arguments to `runCli`, which uses Commander with an explicit target allowlist and constructs discovery, analysis, rendering, validation, and application stages. Plan mode is the default; `ApplyProjectStage` performs preflight without applying artifacts in that mode. Parse errors skip application. Declarative JSON configuration and statically parsed CSS imports are read without loading application code; the loader limits configuration size to 2 MB and CSS imports to 128 visits / depth 16, checks canonical paths against the project root, and snapshots configuration identity and content before application.

The path validator normalizes claims and compares filesystem device/inode identities and existing prefixes to detect collisions, including aliases. The same input/output path is allowed only for the same template's intentional in-place pair. `validateDestination` uses `lstat` and rejects symbolic links and non-regular existing destinations. Validation covers templates, the companion stylesheet, and the report; configuration snapshots are also protected against overlapping outputs.

`MigrationTransaction` seals the exact preflight plan, stages in per-output private namespaces, observes parent and file identities, captures backups, checks original bytes before replacement, and rolls back committed entries in reverse order on failure. Recovery verifies original states and preserves entries whose ownership cannot be confirmed. This is an inspected implementation and regression-suite boundary, not a guarantee against every external filesystem race or forced process termination. The real-CLI POSIX symlink-output regression passed with exit 0 for `NPM_CONFIG_USERCONFIG=/dev/null npm run build && NPM_CONFIG_USERCONFIG=/dev/null npx vitest run test/cli/cli.test.ts -t "symbolic-link output"`; the test observed status 1, the symbolic-link rejection message, and unchanged target and input bytes. No validator correction was required.

## Parsing, rendering, and reports

`AngularTemplateParser` calls the pinned Angular compiler with block syntax, whitespace, and line-ending preservation, collects exact source offsets, and emits parse diagnostics without evaluating template expressions. `SourceEditor` rejects invalid and overlapping edit ranges and applies edits backwards. `TemplateProposalValidator` reparses generated output before creating an artifact. Renderer sessions are single-use; finalized native-CSS output contains only referenced owned rules. Native-CSS and Tailwind outputs share semantic planning with target-specific rendering and preservation decisions.

The schema-2 report builder explicitly projects directive names, offsets, statuses, and diagnostics rather than serializing source objects or template contents. Input, output, file, and stylesheet paths are made relative, with a basename fallback for cross-root output. `JsonReportWriter` checks protected-path overlap and uses `AtomicFileWriter`, which exclusively opens staged files in private namespaces and checks their identities before rename and cleanup. Reports remain an intentional filesystem output in plan mode. The real-CLI clean-template privacy regression passed with exit 0 for `NPM_CONFIG_USERCONFIG=/dev/null npm run build && NPM_CONFIG_USERCONFIG=/dev/null npx vitest run test/cli/cli.test.ts -t "plans a clean Tailwind migration"`; parsed plan-report string values contain neither the temporary root nor the source template, and a synthetic report containing the template is detected by the test helper. No production source was changed.
