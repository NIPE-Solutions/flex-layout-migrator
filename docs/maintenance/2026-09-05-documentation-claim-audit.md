# Documentation claim audit — 2026-09-05

## Scope and authority

This audit covers the public text in `README.md`, `website/content/**/*.md`, `website/src/**/*.ts`, and `website/src/**/*.tsx`, excluding test-only copy. A human review and scoped search considered claims about automation, safety, stability, performance, versions, compatibility, browser privacy, and transactions.

Claims were checked in this order: production implementation and executable tests, typed public contracts and schemas, authored repository documentation, then website summaries. `scripts/verify-documentation-contract.mjs` enforces the CLI, diagnostic, compatibility, report, and verified-example facts against higher-authority sources.

## Enforcement boundaries

- **Registry-enforced facts:** `scripts/verify-documentation-contract.mjs` checks the structured CLI, diagnostic, compatibility, report, and verified-example registries against their production sources and fixtures. It does not treat every sentence in the documentation as a registry fact.
- **Static metadata and link contracts:** `scripts/verify-website-static.mjs`, route-manifest tests, asset verification, and content-loader tests enforce the emitted route set, exact crawler policy and sitemap URL set, canonical and social metadata, redirects and rewrites, required assets, and internal route/fragment validity.
- **Targeted exact public-copy tests:** focused assertions protect selected high-risk statements and labels, including the review-before-write promise, report side effect, preservation language, browser-preview status, privacy qualification, issue-form redaction warning, and footer destinations.
- **Human-reviewed prose:** all remaining narrative text in `README.md`, `website/content/**`, and `website/src/**` was read and searched for the claim families above, then checked against the cited evidence. The automated suite does not comprehensively validate authored prose or prove the absence of every possible overstatement.

## Route, metadata, and repository UX findings

- All previously published content routes remain exact routes: `/docs`, `/docs/cli`, `/docs/tailwind`, `/docs/native-css`, `/docs/safety`, `/docs/troubleshooting`, `/privacy`, and `/imprint`. The browser registry enforces the six legacy documentation paths in `website/src/content/docs-navigation.ts`; the route manifest and static verifier cover the two legal routes.
- The current manifest contains the root, 25 documentation routes, and two legal routes. `scripts/generate-website-route-html.mjs` emits exactly one route-specific canonical, title, description, Open Graph, and Twitter title/description value for every non-root route, normalizing duplicate seed tags. `scripts/verify-website-static.mjs` rejects missing, duplicate, or conflicting authoritative metadata; requires the exact sitemap URL set and robots policy; checks exact route rewrites; and requires permanent redirects from `/index.html` and all generated `.html` aliases to their canonical paths.
- Public issue forms request codemod, Node.js, and Angular versions; target; exact command; minimal redacted source; diagnostics or report context; and expected semantics. Both forms warn against secrets and confidential project code and direct vulnerability reports to GitHub private vulnerability reporting.
- The footer exposes the exact groups Project, NIPE, Legal, and License. `NIPE Open Source` retains the exact destination `https://opensource.nipesolutions.com`.
