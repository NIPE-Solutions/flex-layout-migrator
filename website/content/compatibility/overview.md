# Compatibility overview

## Read status as a proof boundary

Compatibility depends on the directive, selected target, exact source form, responsive family, and surrounding ownership. A Limited entry means verified cases exist; it does not promise conversion for every value. Preserved means the target deliberately leaves recognized source visible. Planned is not current conversion support. Not applicable identifies a separate migration path rather than a layout-target conversion.

Result status is more specific than the matrix. Converted means this occurrence received proven output. Review marks unresolved runtime, precedence, configuration, or context evidence. Unsupported marks recognized semantics outside the selected renderer. Invalid marks source outside the accepted grammar or semantic contract. Parse errors prevent a validated application plan.

## Filter the public registry

The explorer reads the immutable public compatibility registry verified against production directive definitions and executable compatibility evidence. Select a target first, then narrow by family or status. Each directive disclosure shows both target statuses, links matching exact fixtures from the verified example registry, and links to registry-backed diagnostic behavior.

:::compatibility-explorer

## Use the observed diagnostic

The registry is the planning boundary, while the result attached to a source occurrence is the decision record. Static input may still remain unchanged because of a bound class, existing utility, unsafe parent context, intersecting responsive values, or a dependent family on the same element.

When source is preserved, follow the [diagnostic reference](/docs/diagnostics) before changing it. Removing a directive solely to make a repository search pass discards the source behavior the diagnostic is protecting.
